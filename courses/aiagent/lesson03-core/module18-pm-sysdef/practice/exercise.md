# 演習：画面設計を共通ルールへ落とす

Module 18のPRD・要件定義・画面設計を進めるときは、[デザインシステムを作る演習](../../../../../docs/practical-workflow/04-design-system.md)を併用してください。

## 目的と前提

利用者と画面の目的を決めたあと、色・文字・余白・共通部品・4状態をファイルにまとめます。HTMLを表示できるブラウザと、ファイルを扱えるAI環境を使います。Figmaは発展課題で、必須ではありません。

## 手順と成果物（45分）

1. 架空の見積一覧・詳細の利用目的を `design/decisions.md` に書く。
2. `tokens.css` で共通の色・文字・余白に名前を付ける。
3. `components.md` で部品と通常・空・処理中・失敗の状態を定義する。
4. AIへ3ファイルを渡し、静的な `prototype.html` を作る。
5. 390pxと1280pxで見た目を確認し、計算・保存などの機能確認とは分けて記録する。

## 完了条件

- [ ] 同じ部品とトークンを一覧・詳細で再利用できる
- [ ] 4状態の文言と操作可否が決まっている
- [ ] トークン1か所の変更が見本と作成した画面の両方へ反映される
- [ ] 未実装の機能を動作確認済みにしていない

操作場所、コピーする入力、つまずきへの対処、提出物は[追加演習本文](../../../../../docs/practical-workflow/04-design-system.md)を参照してください。実装へ進むときは、この画面ルールに加え、Module 18で扱うAPI・データ・テストの設計が必要です。
