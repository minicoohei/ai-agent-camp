# 参照テキスト: ファインチューニング

## ファインチューニングとは

事前学習済みモデルを特定のタスクやドメインのデータで追加学習する手法。汎用モデルを専門的な用途に最適化します。

## 手法の比較

### Full Fine-Tuning（フルFT）
- モデル全体のパラメータを更新
- 最高の性能が期待できるが、コストが非常に高い
- 大量のGPUメモリと計算時間が必要
- 数百〜数千のGPU時間

### LoRA（Low-Rank Adaptation）
- モデル全体ではなく、低ランク行列を追加して学習
- オリジナルの重みは凍結（変更しない）
- メモリ使用量: フルFTの10〜30%
- 性能はフルFTに匹敵する場合が多い

### QLoRA（Quantized LoRA）
- LoRA + モデル量子化（4bit等）を組み合わせ
- メモリ使用量: フルFTの5〜15%
- コンシューマGPU（24GB VRAM）でも実行可能
- 性能低下は最小限

## 適用判断フロー

```
質問1: プロンプトエンジニアリングで十分な品質が出るか？
  → はい → ファインチューニング不要
  → いいえ ↓

質問2: RAG で解決できるか？（知識不足の問題）
  → はい → RAG を採用
  → いいえ ↓

質問3: 学習データは十分あるか？（最低100〜1000サンプル）
  → いいえ → Few-shot / データ収集を先に
  → はい ↓

質問4: 予算はあるか？
  → 潤沢 → Full Fine-Tuning
  → 限定的 → LoRA / QLoRA
  → 最小 → QLoRA（コンシューマGPU）
```

## コスト・品質トレードオフ

| 手法 | コスト | 性能 | メモリ | 学習時間 |
|------|--------|------|--------|---------|
| プロンプトエンジニアリング | 無料 | 中 | 0 | 即時 |
| RAG | 低 | 中〜高 | 低 | 低 |
| QLoRA | 中 | 高 | 8〜24GB | 数時間 |
| LoRA | 中〜高 | 高 | 24〜80GB | 数時間 |
| Full FT | 非常に高 | 最高 | 数百GB | 数日 |

## ファインチューニングが有効なケース

- **スタイル適応**: 特定の文体・トーンで出力させたい
- **ドメイン特化**: 医療、法律等の専門用語を正確に使わせたい
- **フォーマット固定**: 常に特定の JSON スキーマで出力させたい
- **レイテンシ削減**: プロンプトを短くしてレスポンス速度を上げたい

## ファインチューニングが不要なケース

- 最新情報が必要 → RAG
- タスクが頻繁に変わる → プロンプトエンジニアリング
- 少量データしかない → Few-shot Learning
- 一般的な質問応答 → 標準モデルで十分
