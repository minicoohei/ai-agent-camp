# 参照テキスト: RAG（Retrieval-Augmented Generation）

## RAG とは

検索拡張生成。LLM の知識を外部データで補完する手法。モデルの訓練データに含まれない最新情報や社内データを、推論時に動的に提供します。

## 4ステップ

### 1. Ingestion（データ取り込み）
外部データをベクトルDB に格納する前処理。

- **ドキュメント収集**: PDF、Webページ、DB、API からデータ取得
- **チャンキング**: ドキュメントを適切なサイズに分割
- **Embedding**: テキストチャンクをベクトル（数値配列）に変換
- **インデックス作成**: ベクトルDB に格納

### 2. Retrieval（検索）
ユーザーの質問に関連するチャンクを検索。

- クエリテキストを Embedding でベクトル化
- ベクトル DB でコサイン類似度による近似検索
- 上位 k 件の関連チャンクを取得

### 3. Augmentation（コンテキスト拡張）
検索結果をプロンプトに組み込む。

```
以下の情報を参考に質問に答えてください:

[検索結果1]
...

[検索結果2]
...

質問: {ユーザーの質問}
```

### 4. Generation（生成）
拡張されたコンテキストを元に LLM が回答を生成。

## ベクトルデータベース

| DB | 特徴 | 用途 |
|-----|------|------|
| Pinecone | フルマネージド | 本番環境向け |
| Chroma | 軽量・組み込み | プロトタイプ |
| Weaviate | GraphQL 対応 | 複雑なクエリ |
| Qdrant | Rust 製・高速 | 大規模データ |
| pgvector | PostgreSQL 拡張 | 既存 DB 活用 |
| FAISS | Meta 製・ローカル | 研究・実験 |

## チャンキング戦略

### 固定サイズ分割
- テキストを一定文字数で分割
- 簡単だが、文脈が途切れる可能性

### セマンティック分割
- 意味的なまとまりで分割
- 段落、セクション、トピック単位

### オーバーラップ
- 隣接チャンク間で一部テキストを重複させる
- 文脈の断絶を軽減

### 再帰的分割
- 見出し → 段落 → 文 の階層で分割
- LangChain の RecursiveCharacterTextSplitter が代表的

## RAG の課題と対策

| 課題 | 対策 |
|------|------|
| 検索精度が低い | Embedding モデルの改善、ハイブリッド検索 |
| チャンクサイズの最適化 | 用途に応じた実験と調整 |
| 最新性の維持 | 定期的なインデックス更新 |
| ハルシネーション | 引用元の明示、ファクトチェック |
