# 参照テキスト: コンテキスト設計

## コンテキストウィンドウとは

LLM が一度の推論で参照できるテキスト量の上限。入力（プロンプト）と出力（レスポンス）の合計トークン数がこの範囲内に収まる必要があります。

| モデル | コンテキストウィンドウ |
|--------|---------------------|
| Claude 3.5 Sonnet | 200K トークン |
| GPT-4o | 128K トークン |
| Gemini 2.0 Flash | 1M トークン |

## コンテキストの構造

```
┌─────────────────────────────┐
│ システムプロンプト           │ ← 役割・制約・ルール
├─────────────────────────────┤
│ ツール定義                   │ ← 使用可能なツールの仕様
├─────────────────────────────┤
│ ユーザーメッセージ           │ ← ユーザーの指示
├─────────────────────────────┤
│ コンテキスト情報             │ ← ファイル内容、検索結果等
├─────────────────────────────┤
│ 会話履歴                     │ ← 過去のやり取り
├─────────────────────────────┤
│ 出力                         │ ← モデルの応答
└─────────────────────────────┘
```

## システムプロンプト

モデルの振る舞いを制御する最初の指示。会話全体を通じて適用される。

### 効果的なシステムプロンプトの要素
- **役割定義**: 「あなたは○○の専門家です」
- **制約条件**: 「日本語で回答してください」
- **出力形式**: 「JSON形式で出力してください」
- **安全ガイドライン**: 「機密情報は出力しないでください」

## プロンプト設計パターン

### Few-shot Learning
具体例を提示してパターンを学習させる。

```
入力: "The cat sat on the mat"
出力: 名詞: cat, mat / 動詞: sat

入力: "Dogs run in the park"
出力: 名詞: Dogs, park / 動詞: run

入力: "Birds fly over the ocean"
出力:
```

### Chain of Thought（CoT）
段階的に思考させることで推論精度を向上させる。

```
問題: 農場に鶏が5羽と牛が3頭います。足の合計は何本ですか？

考え方を段階的に示してください:
1. 鶏は1羽あたり2本の足 → 5 x 2 = 10本
2. 牛は1頭あたり4本の足 → 3 x 4 = 12本
3. 合計: 10 + 12 = 22本
```

### プロンプト vs コンテキストエンジニアリング

| 観点 | プロンプトエンジニアリング | コンテキストエンジニアリング |
|------|------------------------|--------------------------|
| 範囲 | ユーザーの指示文の最適化 | コンテキスト全体の設計 |
| 対象 | プロンプトテキスト | システムプロンプト、ツール、データ全体 |
| 目的 | 出力品質の向上 | エージェント全体の動作最適化 |
| 例 | Few-shot、CoT | CLAUDE.md、スキル定義、RAG |

## CLAUDE.md の役割

プロジェクト固有のコンテキスト情報をファイルとして提供する仕組み。Claude Code はこのファイルを自動的に読み込み、プロジェクトの構造やルールを理解する。
