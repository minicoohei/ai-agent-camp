# API キーセキュリティチェックリスト

## 必須チェック項目

- [ ] **1. .env ファイルが .gitignore に含まれている**
  ```bash
  grep ".env" .gitignore
  # .env が含まれていることを確認
  ```

- [ ] **2. .env ファイルがコミット履歴に含まれていない**
  ```bash
  git log --all --full-history -- .env
  # 出力がなければOK
  ```

- [ ] **3. API キーがソースコードにハードコードされていない**
  ```bash
  grep -r "sk-ant-\|sk-\|AIza" --include="*.py" --include="*.js" --include="*.ts" .
  # 出力がなければOK（.env.example は除く）
  ```

- [ ] **4. .env.example にはダミー値のみ記載されている**
  ```bash
  cat .env.example
  # 実際のキー値が含まれていないことを確認
  ```

- [ ] **5. API キーに必要最小限の権限が設定されている**
  - 読み取り専用で十分な場合は書き込み権限を付与しない
  - 特定のリソースのみアクセス可能にする

- [ ] **6. API キーのローテーション計画がある**
  - 定期的に（3ヶ月〜6ヶ月ごと）キーを更新する
  - 古いキーは速やかに無効化する

- [ ] **7. GitHub Secrets に機密情報を保存している（CI/CD使用時）**
  - リポジトリの Settings → Secrets and variables → Actions
  - ワークフロー内では `${{ secrets.KEY_NAME }}` で参照

- [ ] **8. 環境変数の読み込みに python-dotenv を使用している**
  ```python
  from dotenv import load_dotenv
  load_dotenv()
  ```

- [ ] **9. エラーメッセージに API キーが含まれないことを確認**
  - ログ出力時にキーをマスクする
  - スタックトレースにキーが露出しないようにする

- [ ] **10. 不要になった API キーは速やかに削除・無効化している**
  - 各サービスの管理画面で無効化
  - .env から該当行を削除

## やってはいけないこと

| NG行為 | 理由 |
|--------|------|
| API キーを Slack やメールで共有 | 傍受・漏洩リスク |
| API キーをソースコードにハードコード | Git 履歴に永続的に残る |
| .env ファイルを Git にコミット | 公開リポジトリの場合即漏洩 |
| 全権限のキーを開発に使用 | 最小権限の原則に違反 |
| キーの使い回し | 1つ漏洩で全サービス影響 |

## 万が一漏洩した場合

1. **即座にキーを無効化**（各サービスの管理画面）
2. **新しいキーを発行**して .env を更新
3. **Git 履歴から削除**（`git filter-branch` または BFG Repo-Cleaner）
4. **影響範囲の確認**（不正利用のログを確認）
5. **チームへの共有**（同じキーを使っている人に通知）
