# PM Toolkit - プロダクトマネジメントツールキット

プロダクト開発の企画・要件定義フェーズで使うテンプレートとプロンプトを提供します。

## Workflow

1. ユーザーが作成したい成果物を指定（PRD/要件定義書/レビュー等）
2. 該当テンプレートを適用し、対話的に情報を収集
3. 構造化されたドキュメントを `output/pm/` に生成

## Templates

### PRDテンプレート（Working Backwards方式）

```markdown
# PRD: {プロダクト名}

## 1. プレスリリース
### ヘッドライン
{1行で価値を伝えるタイトル}

### サブヘッドライン
{ターゲットユーザーと主要ベネフィット}

### 課題
{ユーザーが抱える問題 3点}

### ソリューション
{プロダクトがどう解決するか}

### お客様の声（想定）
{理想的なユーザーの反応}

### 使い方
{3ステップで説明}

### CTA
{次のアクション}

## 2. FAQ
### ユーザー向けFAQ（5問）
### ステークホルダー向けFAQ（5問）

## 3. ユーザーストーリー
| ID | ペルソナ | As a... | I want to... | So that... | 優先度 |
|----|---------|---------|-------------|-----------|--------|

## 4. スコープ
### In Scope（MVP）
### Out of Scope（v2以降）

## 5. 成功指標（KPI）
| 指標 | 現状 | 目標 | 計測方法 |
|-----|------|------|---------|
```

```markdown
|----|--------|------|--------|------|

- 入力:
- 処理:
- 出力:
- 制約条件:

## 3. 非機能要件
### 3.1 性能要件
| 項目 | 要件 | 根拠 |
|------|------|------|
| レスポンスタイム | 画面遷移3秒以内 | UX基準 |
| 同時接続数 | 100ユーザー | 想定利用人数 |

### 3.2 セキュリティ要件
### 3.3 可用性要件
### 3.4 移行要件

## 4. 外部インターフェース
### 4.1 ユーザーインターフェース
### 4.2 外部システム連携

## 5. 制約条件・前提条件
```

### 要求資料テンプレート

```markdown
# 要求資料: {プロジェクト名}

### Should Have（推奨）
### Could Have（あると良い）
### Won't Have（今回は対象外）

## 非機能要求
| カテゴリ | 要求 | 優先度 | 備考 |
|---------|------|--------|------|
```

### レビュープロンプト

#### Devil's Advocate レビュー
AIが以下の観点で反論・指摘を行う:
- この機能は本当に必要か？根拠は？
- もっとシンプルな代替案はないか？
- 最悪のシナリオは？そのリスクは許容可能か？
- ターゲットユーザーは本当にこれを求めているか？
- 技術的に実現可能か？コストは妥当か？

#### セキュリティレビュー（STRIDE）
| 脅威 | 説明 | TaskFlowでの該当箇所 | 対策 |
|------|------|---------------------|------|
| Spoofing | なりすまし | 認証機能 | |
| Tampering | 改ざん | タスクデータ | |
| Repudiation | 否認 | 操作ログ | |
| Information Disclosure | 情報漏洩 | ユーザーデータ | |
| Denial of Service | サービス妨害 | API | |
| Elevation of Privilege | 権限昇格 | 管理者機能 | |

```markdown
| # | 内容 | 担当 | 期限 | 状態 |
|---|------|------|------|------|
```

#### 議事録→仕様変更抽出プロンプト
以下の議事録を分析し、仕様変更に該当する箇所を抽出してください:
- 変更内容
- 影響範囲（関連する要件ID）
- 変更理由
- 対応優先度

## Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| template | Yes | - | 使用するテンプレート（prd/requirements/review/meeting） |
| product_name | No | TaskFlow | プロダクト名 |
| output_dir | No | output/pm/ | 出力ディレクトリ |

## Output Format

Markdown形式のドキュメントを指定ディレクトリに出力:
- PRD → `output/pm/prd.md`
- 要件定義書 → `output/pm/requirements-spec.md`
- 要求資料 → `output/pm/requirements-brief.md`
- レビュー → `output/pm/review-{type}.md`
- 議事録 → `output/pm/meeting-minutes.md`

## Example

```
pm-toolkitスキルを使って、TaskFlowのPRDをWorking Backwards方式で作成してください。
→ output/pm/prd.md が生成される
```
