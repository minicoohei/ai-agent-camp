# 3. 測って直すループを回す

[演習一覧](README.md) → この演習 → [デザインシステム](04-design-system.md)

「良くなるまで直して」を、判定できる小さな作業へ変える30分の演習です。[基礎の観察→判断→行動](../../courses/aiagent/lesson01-foundation/ch03-agents/practice/reference.md)を、テストと記録で体験します。

## ループを始める前に4点を固定する（5分）

| 決めること | 今回の値 |
| --- | --- |
| 測定方法 | 同じ `checks.py` を同じフォルダで実行する |
| 合格条件 | 固定4テストがすべて成功し、期待値を変更していない |
| 上限 | 修正→再実行を最大3回。15分に達した場合も停止 |
| 提出物 | `quote.py`、`evidence/loop.md`、修正前後の実行結果と差分 |

これは観測した失敗を次の修正へ渡す品質改善です。一定時間ごとに同じ処理を起動する定期実行とは分けて考えます。専用の `/loop` コマンドや自動判定機能がなくても、同じ手順を回せます。

## 未修正のコピーを用意する（5分）

演習1の修正を消さないよう、教材の [starter](starter/) の中身を別の新規フォルダ `camp-loop-practice` へコピーし、AIの作業場所を切り替えます。同名があれば止まります。履歴を戻すコマンドは使いません。

ターミナルで `python3 checks.py` を実行します。初回は4件中2失敗です。これを `evidence/loop.md` に「0回目・修正前」として記録します。初回測定は修正回数に含めません。

## 失敗を次の依頼へ渡す（15分以内）

AIチャットへの依頼文：

```text
README.md の仕様と checks.py の実行結果を読み、quote.py だけを修正してください。
固定4テストの全成功を合格とし、修正→同じテストの再実行は最大3回、または15分で止めてください。
時間を計測できなければその旨を伝え、人のタイマーで15分を管理します。
毎回、失敗したテスト名、期待値と実測値、変更理由、再実行結果を evidence/loop.md に追記してください。
checks.py と仕様は変更しません。同じ失敗が2回続き、原因を特定できない場合も停止してください。
最後に合格／上限／原因不明のどれで止まったか、残る問題と次に調べる1点を報告してください。
commit・外部通信は行いません。
```

毎回、人はテストが実行されたことと修正範囲を確認します。期待値を書き換える、失敗テストを削除する、コマンドを実行せず成功と述べる、は改善に数えません。

`evidence/loop.md` の例（結果は自分の実測値に置換）：

| 回 | 観測 | 判断と変更 | 再測定 | 次の行動 |
| --- | --- | --- | --- | --- |
| 0 | 4件中2失敗 | まず全明細を読む | 未修正 | 原因候補を確認 |
| 1 | 最後の明細が未計上、境界で値引きなし | 合計範囲と境界条件を修正 | 4件成功／実際の結果を記載 | 条件を満たせば停止 |

初回の修正で合格したら、3回まで続ける必要はありません。上限に達した場合も途中の成果物と失敗ログを残します。合格と記録せず、再開時に入力・仕様・環境のどれを見直すかを1つ指定します。

## 別の仕事へ置き換える（5分）

画面なら同じ表示幅・状態で比較し、文字切れ件数や部品の余白を測ります。資料なら主張ごとの根拠数や未確認項目数を使います。AIの採点は補助です。数値、実行ログ、原資料との照合を併せて使います。採点だけが上がっていても根拠が増えなければ完了にしません。

- [ ] 測定方法・合格条件・上限・提出物を開始前に決めた
- [ ] 修正前の2失敗と修正後の実測結果がある
- [ ] 固定テストを改変していない
- [ ] 合格または停止条件に達した時点で止まった
- [ ] 未達の場合は原因候補と再開位置が記録されている
