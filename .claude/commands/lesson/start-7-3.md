# 🎓 Lesson 7-3: テストとイテレーション

## 📍 このセッションでやること

**Lesson 7-3: テストとイテレーション** へようこそ！

| 項目 | 内容 |
|------|------|
| ゴール | 作成した議事録スキルを3種のテストで検証し、改善サイクルを回す |
| 所要時間 | 約25分 |
| 使うスキル | meeting-notes-summarizer（Lesson 7-2で作成） |
| 前提条件 | Lesson 7-2 完了（SKILL.md作成済み） |

**このセッションの流れ:**
1. トリガーテストの実施
2. 機能テスト（サンプルデータ3種）
3. パフォーマンス比較（スキルあり/なし）
4. 5つの典型的トラブルパターンの診断
5. 改善ループの実践

セッション終了時には、スキルの品質を客観的に評価し、改善サイクルを回せるようになっています。

> **💡 ヒント**: AIの応答が途中で止まった場合は「続きを表示して」「止まってるよ」と入力すると再開します。これはCursorの仕様で、故障ではありません。

## 🚀 Step 1: トリガーテストの実施

**AskQuestionの設定例:**
```json

      {"id": "skip", "label": "スキップする"}
    ]
  }]

```

**選択後の案内（例）**:
入力内容:
```

以下のフレーズを1つずつ入力し、スキルが正しく発動するか確認してください。

【正しく発動すべきフレーズ（5つ）】

1. 「議事録をまとめて」
2. 「会議メモを整理して」
3. 「アクション項目を抽出して」
4. 「ミーティングノートを構造化して」
5. 「この会議の要点をまとめて」

→ 期待結果: すべてのフレーズで meeting-notes-summarizer スキルが発動すること

【発動すべきでないフレーズ（3つ）】

1. 「メールをまとめて」
2. 「Slackのメッセージを検索して」
3. 「レポートを作成して」

→ 期待結果: これらのフレーズではスキルが発動しないこと

【テスト結果の記録方法】
以下の形式で結果を記録してください：

| フレーズ | 期待 | 実際 | 結果 |
|----------|------|------|------|
| 議事録をまとめて | 発動する | ? | OK/NG |
| 会議メモを整理して | 発動する | ? | OK/NG |
| アクション項目を抽出して | 発動する | ? | OK/NG |
| ミーティングノートを構造化して | 発動する | ? | OK/NG |
| この会議の要点をまとめて | 発動する | ? | OK/NG |
| メールをまとめて | 発動しない | ? | OK/NG |
| Slackのメッセージを検索して | 発動しない | ? | OK/NG |
| レポートを作成して | 発動しない | ? | OK/NG |

8つ中、何個正しく動作したかを確認してください。
合格ライン: 8/8（全問正解）
```

**期待される結果**: すべての正しいトリガーがスキルを発動し、不正なトリガーでは発動しないことが確認できます。

## 🚀 Step 4: 5つの典型的トラブルパターンの診断

AskUserQuestion（AskQuestion）で「このまま進める / 例だけ確認 / スキップ」を選べます。

**AskQuestionの設定例:**
```json
{
  "title": "🚀 Step 4: 5つの典型的トラブルパターンの診断",
  "questions": [{
    "id": "step_action",
    "prompt": "このステップをどうしますか？",
    "options": [
      {"id": "practice", "label": "このまま進める"},

    ]
  }]
}
```

**選択後の案内（例）**:
入力内容:
```
スキル開発でよくある5つのトラブルパターンを確認し、
自分のスキルに当てはまるものがないか診断してください。

【パターン1: undertriggering（発動不足）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

症状: スキルが発動すべきなのに発動しない
原因: SKILL.md の description に含まれるトリガーフレーズが不足している

診断方法:
1. Step 1 のトリガーテスト結果を確認
2. 「発動すべきなのに発動しなかった」フレーズがあるか確認
3. あれば、SKILL.md の description にそのフレーズを追加

修正例:
修正前: description: "会議の議事録を構造化してまとめるスキル"
修正後: description: "会議の議事録・ミーティングノート・会議メモを構造化してまとめるスキル。アクション項目の抽出や要点整理にも対応"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【パターン2: overtriggering（過剰発動）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

症状: 関係ない場面でスキルが発動する
原因: description が広すぎる（「まとめて」だけだと何でもマッチしてしまう）

診断方法:
1. Step 1 のトリガーテスト結果を確認
2. 「発動すべきでないのに発動した」フレーズがあるか確認
3. あれば、description を「会議」「議事録」に限定した表現に修正
```

## ⚠️ よくあるトラブルと解決方法

AskUserQuestion（AskQuestion）でトラブル内容を選んでもらい、押すだけで案内します。

**AskQuestionの設定例:**
```json

      {"id": "trouble_2", "label": "スキルのあり/なしの切り替え方が分からない"},
      {"id": "trouble_3", "label": "改善しても出力が変わらない"},
      {"id": "trouble_4", "label": "テスト結果の記録方法が分からない"}
    ]
  }]
}
```

### トラブル1: テスト用サンプルデータがない
**原因**: テスト用の議事録データを自分で用意できない
**解決プロンプト**:
```
Step 2 にインラインで3種類のサンプルデータを用意しています。
そのまま使用してください：
- サンプル1: 短い会議（3人、5分）
- サンプル2: 定例会議（5人、30分）
- サンプル3: 英語混在ワークショップ
```

### トラブル2: スキルのあり/なしの切り替え方が分からない
**原因**: スキルの無効化・有効化の方法を知らない
**解決プロンプト**:
```
skills/ ディレクトリ内のスキルフォルダ名を変更することで無効化できます。

無効化（名前変更で一時的に非表示にする）:
mv skills/meeting-notes-summarizer skills/_meeting-notes-summarizer_disabled

有効化（元の名前に戻す）:
mv skills/_meeting-notes-summarizer_disabled skills/meeting-notes-summarizer

注意: テスト後は必ず有効化に戻してください。
```

### トラブル3: 改善しても出力が変わらない
**原因**: SKILL.md の変更がキャッシュされている可能性がある
**解決プロンプト**:
```
以下の手順を試してください：
1. エディタ（Cursor）を再起動する
2. SKILL.md ファイルを保存し直す（Ctrl+S / Cmd+S）
3. 新しいチャットセッションで再度テストする
4. それでも変わらない場合、SKILL.md の変更内容が正しく保存されているか確認：
   cat skills/meeting-notes-summarizer/SKILL.md
```

### トラブル4: テスト結果の記録方法が分からない
**原因**: テスト結果の保存先やフォーマットが不明
**解決プロンプト**:
```
output/ ディレクトリにMarkdown形式で保存してください。

mkdir -p output

テスト結果の保存先:
- トリガーテスト結果: output/trigger-test-results.md
- 機能テスト結果: output/functional-test-results.md
- パフォーマンス比較: output/performance-comparison.md
- 改善レポート: output/skill-improvement-report.md

フォーマット例:

| フレーズ | 期待 | 実際 | 結果 |
|----------|------|------|------|
| 議事録をまとめて | 発動 | 発動 | OK |
...
```
