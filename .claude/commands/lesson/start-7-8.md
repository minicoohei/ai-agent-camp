# 🎓 Lesson 7-8: テスト・デバッグ・イテレーション

## 📍 このセッションでやること

**Lesson 7-8: テスト・デバッグ・イテレーション** へようこそ！

| 項目 | 内容 |
|------|------|
| ゴール | 作成したSkill/Commandの品質を検証し、改善する |
| 所要時間 | 約30分 |

**選択後の案内（例）**:

各Commandについて、以下の3つの観点でテストします。

入力内容:
```
7-6 で作成した3つのCommandを以下の観点でテストしてください：

### テスト1: 正常系テスト
各コマンドを /コマンド名 で実行し、期待通りの出力が得られるか確認：

- /daily-report → 日報テンプレートが正しく表示されるか
  - 日付が正しいか
  - テーブル形式が崩れていないか
  - チェックボックスが機能するか

- /meeting-prep → 会議準備チェックリストが正しく表示されるか
  - チェック項目が抜け漏れなく表示されるか
  - アジェンダテンプレートのテーブルが崩れていないか

- /code-review → レビューガイドが正しく表示されるか
  - カテゴリ分けが適切か
  - コメントテンプレートがコピペで使えるか

### テスト2: エッジケーステスト
- コマンドの説明文が長すぎる場合、表示は崩れないか
- Markdown記法（コードブロック、テーブル、チェックボックス）が全て正しくレンダリングされるか
- 日本語と英語が混在しても問題ないか

### テスト3: ユーザビリティテスト
- 初見のユーザーが見て、使い方が分かるか
- 不要な情報がないか（情報過多でないか）
- 必要な情報が不足していないか

テスト結果を以下の形式でレポートしてください：

| コマンド | 正常系 | エッジケース | ユーザビリティ | 総合判定 |
|----------|--------|------------|--------------|---------|
| daily-report | OK/NG | OK/NG | OK/NG | PASS/FAIL |
| meeting-prep | OK/NG | OK/NG | OK/NG | PASS/FAIL |
| code-review | OK/NG | OK/NG | OK/NG | PASS/FAIL |
```

**期待される結果**: 3つのCommandのテスト結果レポートが完成し、問題点が明確になる。

## ⚠️ よくあるトラブルと解決方法

Codex では通常チャットで選択肢を提示しながらでトラブル内容を選んでもらい、押すだけで案内します。

**AskQuestionの設定例:**
```json
{
  "title": "トラブル内容を選択",
  "questions": [{
    "id": "trouble",
    "prompt": "当てはまる内容を1つ選んでください",
    "options": [
      {"id": "trouble_1", "label": "テストで予想外のエラーが出る"},
      {"id": "trouble_2", "label": "修正しても同じエラーが再発する"},
      {"id": "trouble_3", "label": "レビュー観点が多すぎて何から手を付ければいいか分からない"},
      {"id": "trouble_4", "label": "ドキュメントの書き方が分からない"}
    ]
  }]
}
```

### トラブル1: テストで予想外のエラーが出る
**原因**: テスト環境とスクリプトの想定が異なる
**解決プロンプト**:
```
エラーメッセージを全文貼り付けてください。以下の順で原因を切り分けます：
1. Python のバージョンは？（python3 --version）
2. 必要なパッケージは全てインストールされているか？（uv pip list）
3. ファイルパスは正しいか？（ls -la で確認）
4. 環境変数は設定されているか？（echo $VARIABLE_NAME）
```

### トラブル2: 修正しても同じエラーが再発する
**原因**: 修正箇所が間違っている、またはキャッシュの問題
**解決プロンプト**:
```
以下を試してください：
1. ファイルを保存し直す（Cmd+S / Ctrl+S）
2. Python キャッシュを削除: find . -name "__pycache__" -exec rm -rf {} +
3. ファイルの変更が反映されているか確認: cat [ファイルパス] | head -20
4. 別のターミナルウィンドウで実行してみる
```

### トラブル3: レビュー観点が多すぎて何から手を付ければいいか分からない
**原因**: 完璧主義に陥っている
**解決プロンプト**:
```
80%ルールを適用してください：
1. まず「動くか動かないか」だけ確認する（Critical）
2. 次に「使いやすいか」を確認する（High）
3. 残りは「あったら嬉しい」レベル（Medium/Low）
Critical と High だけ修正すれば、このレッスンは完了です。
```

### トラブル4: ドキュメントの書き方が分からない
**原因**: 良いドキュメントの例を見ていない
**解決プロンプト**:
```
以下の既存スキルのSKILL.mdを参考にしてください：
- skills/banner-creator/SKILL.md（シンプルな例）
- skills/data-analyst/SKILL.md（詳細な例）

ドキュメントは「自分が3ヶ月後に読んで分かるか？」を基準に書いてください。
```
