# 🎓 Lesson 7-6: 自分のワークフロー用Command作成

## 📍 このセッションでやること

**Lesson 7-6: 自分のワークフロー用Command作成** へようこそ！

| 項目 | 内容 |
|------|------|
| ゴール | 自分の業務ワークフローに合わせたカスタムCommandを3つ作成する |
| 所要時間 | 約35分 |
| 使うスキル | Markdown（YAML frontmatter）、Cursor Commands |
| 前提条件 | Lesson 7-5 完了（既存Skill/Commandの構造理解） |

**このセッションの流れ:**
1. 日常業務のワークフローを洗い出す（AskUserQuestion使用）
2. 最初のCommand作成：日報/週報テンプレート生成
3. 2つ目のCommand作成：会議準備チェックリスト
4. 3つ目のCommand作成：コードレビューガイド
5. 動作確認（/command-name で実行）

セッション終了時には、自分の業務に直結する3つのカスタムCommandが使えるようになっています。

> **💡 ヒント**: AIの応答が途中で止まった場合は「続きを表示して」「止まってるよ」と入力すると再開します。ツールによって応答が途中で止まることがありますが、故障ではありません。

## 🚀 Step 1: 日常業務のワークフローを洗い出す

まずはあなたの日常業務を整理して、自動化・テンプレート化できるタスクを見つけましょう。

```json

  "questions": [{

**選択後の案内（例）**:

```

4. その作業で「毎回忘れがちなチェック項目」はありますか？
5. その作業を自動化できたら、どれくらい時間が節約できそうですか？

回答をもとに、Command化すべき3つのワークフローを提案してください。
```

**期待される結果**: Command化する3つのワークフローが決定する。

      {"id": "review", "label": "例だけ確認する（サンプルを見る）"},
      {"id": "skip", "label": "スキップする"}
    ]
  }]
}
```

**選択後の案内（例）**:

入力内容:
```
.cursor/commands/utility/code-review.md を作成してください。以下の内容で：

---
description: "コードレビューのガイドラインとチェックリスト"
---

# コードレビューガイド

## 使い方
レビュー対象のファイル名やPR番号を入力すると、レビューポイントが生成されます。

## 🔍 レビューチェックリスト

### 1. 可読性
- [ ] 変数名・関数名は意図が明確か
- [ ] コメントは「なぜ」を説明しているか（「何を」ではなく）
- [ ] 関数は1つの責務に集中しているか（20行以内が目安）
- [ ] ネストが深すぎないか（3段階以内）

### 2. 正確性
- [ ] エッジケースは処理されているか（null, 空配列, 境界値）
- [ ] エラーハンドリングは適切か（try-catch, バリデーション）
- [ ] 型の不整合はないか
- [ ] 既存テストは全てパスするか

### 3. セキュリティ
- [ ] ハードコードされた秘密情報はないか（API キー、パスワード）
- [ ] ユーザー入力のサニタイズは行われているか
- [ ] 適切なアクセス制御が設定されているか

### 4. パフォーマンス
- [ ] 不要なループ・計算はないか
- [ ] N+1 問題は発生しないか
- [ ] 大量データの処理でメモリリークの可能性はないか

### 5. テスト
- [ ] 新しいロジックにテストが追加されているか
- [ ] テストはエッジケースをカバーしているか
- [ ] テストは独立して実行可能か

## 💬 レビューコメントのテンプレート

### 修正必須（Blocker）
```
🚫 [Blocker] ○○が△△になっています。□□に修正してください。
理由: ...
```

### 提案（Suggestion）
```
💡 [Suggestion] ○○を△△にすると、□□が改善されると思います。
参考: ...
```

### 質問（Question）
```
❓ [Question] ここで○○している意図を教えてください。
△△のケースではどうなりますか？
```

### 称賛（Praise）
```
👏 [Nice!] ○○の実装が素晴らしいです。△△の点が特に良いと思います。
```
```

**期待される結果**: `/code-review` コマンドが作成され、レビュー時のガイドラインとして使える。

## ⚠️ よくあるトラブルと解決方法

Codex では通常チャットで選択肢を提示しながらでトラブル内容を選んでもらい、押すだけで案内します。

**AskQuestionの設定例:**
```json
{
  "title": "トラブル内容を選択",
  "questions": [{
    "id": "trouble",
    "prompt": "当てはまる内容を1つ選んでください",
    "options": [
      {"id": "trouble_1", "label": "コマンドが /コマンド名 で呼び出せない"},
      {"id": "trouble_2", "label": "テンプレートの内容が自分の業務に合わない"},
      {"id": "trouble_3", "label": "YAMLフロントマターのエラーが出る"},
      {"id": "trouble_4", "label": "コマンドをチームで共有したい"}
    ]
  }]
}
```

### トラブル1: コマンドが /コマンド名 で呼び出せない
**原因**: ファイルの配置場所が間違っている
**解決プロンプト**:
```
以下を確認してください：
1. ファイルが .cursor/commands/ 配下にあるか（サブディレクトリ可）
2. ファイル拡張子が .md になっているか
3. Cursorを再起動して、コマンドパレット（Cmd+Shift+P）で確認
```

### トラブル2: テンプレートの内容が自分の業務に合わない
**原因**: サンプルがそのまま使えるとは限らない
**解決プロンプト**:
```
テンプレートはあくまで「出発点」です。以下の手順でカスタマイズしてください：
1. 不要なセクションを削除
2. 自分の業務特有の項目を追加
3. チーム内で使っている用語に置き換え
4. 実際に1週間使ってみて、過不足を調整
```

### トラブル3: YAMLフロントマターのエラーが出る
**原因**: YAML構文の問題
**解決プロンプト**:
```
よくある原因:
- description の値にコロン(:)が含まれている → ダブルクォートで囲む
- インデントがタブになっている → スペース2つに変更
- --- の前後に余分な空白がある → 削除する
```

### トラブル4: コマンドをチームで共有したい
**原因**: 共有方法が分からない
**解決プロンプト**:
```
2つの方法があります：
1. Gitリポジトリに .cursor/commands/ をコミット（チーム全員がcloneすれば使える）
2. .claude/commands/ にも同じファイルを配置（Claude Code ユーザー向け）
```
