```json

  "title": "🚀 Step 2: セキュリティレビューの範囲",

```

(stride_only → STRIDE 6 項目の分析)
(stride_dataflow → データフロー図も追加分析)
(stride_full → 対策提案まで含める)
(comprehensive → リスク評価・優先度付け含む)

**選択後の案内（例）**:
入力内容:
```text
output/pm/prd.md のTaskFlow を対象に、
STRIDE セキュリティ分析を実施してください。

【STRIDE 6項目の分析】

1. **Spoofing（なりすまし）**
   対象: ユーザー認証
   質問:
   - ユーザー認証方式は？（email/password, OAuth, SSO）
   - なりすまし攻撃のリスクは？
   - 対策: 強力なパスワードポリシー、MFA、セッション管理

2. **Tampering（改ざん）**
   対象: タスクデータ
   質問:
   - タスクデータの整合性を保証するか？
   - 不正なデータ修正のリスクは？
   - 対策: デジタル署名、監査ログ、トランザクション管理

3. **Repudiation（否認）**
   対象: 操作ログ・監査証跡
   質問:
   - 誰が何をしたかを追跡可能か？
   - ユーザーが行動を否定する可能性は？
   - 対策: 完全な操作ログ、タイムスタンプ、改ざん防止

4. **Information Disclosure（情報漏洩）**
   対象: ユーザーデータ（タスク、メッセージなど）
   質問:
   - 他のユーザーデータへのアクセスリスクは？
   - データベースの暗号化は？
   - 通信は暗号化されているか？
   - 対策: TLS/SSL、暗号化ストレージ、アクセス制御

5. **Denial of Service（サービス妨害）**
   対象: API、ウェブサーバー
   質問:
   - 意図的な過負荷攻撃への耐性は？
   - DDoS対策は実装されているか？
   - レート制限は？
   - 対策: WAF、レート制限、キャパシティ計画

6. **Elevation of Privilege（権限昇格）**
   対象: 管理者機能、チーム権限
   質問:
   - 一般ユーザーが管理者権限を得るリスクは？
   - ロールベース アクセス制御（RBAC）の設計は適切か？
   - 対策: 厳格な権限検証、監査ログ、定期的な権限見直し

【データフロー図】
以下のコンポーネント間のデータフローを図示:
- ユーザーブラウザ ← → Webサーバー
- Webサーバー ← → API サーバー
- API サーバー ← → データベース
- API サーバー ← → 通知サービス（email/Slack）

各接続点でのセキュリティを確認してください。

【脅威・対策の表形式】
| 脅威カテゴリ | 脅威 | 影響度 | リスク | 対策 | 実装済み |
|------------|-----|--------|--------|------|---------|
| Spoofing | 認証情報漏洩 | 高 | ユーザーデータ漏洩 | MFA | ✗ |
| Tampering | タスク改ざん | 中 | データ不正 | 監査ログ | ✓ |

完成した分析を markdown で出力してください。
```

**期待される結果**: STRIDE分析に基づくセキュリティレビューが完成します。

**選択後の案内（例）**:
入力内容:
```text
output/pm/prd.md と output/pm/customer-needs.md をもとに、
TaskFlow のビジネスケース分析を実施してください。

【1. 市場規模（Market Sizing）】

TAM（Total Addressable Market）:
- 対象: 日本の 10～100名企業のプロジェクト管理ソフト市場
- 市場規模の推定方法（トップダウン）:
  * 日本の企業数: 約 380万社
  * 10～100名企業: 約 10万社（既存データから）
  * タスク管理ツール導入率: 現在 15%（推定）
  * 平均購買額: 年間 50万円/企業（5ユーザー × 10万円/ユーザー）
  * TAM = 10万 × 50万 = 50億円/年

SAM（Serviceable Addressable Market）:
- TaskFlow がターゲットする市場
- 対象: 10～100名企業のうち、Asana/Trello に不満層
- 推定: TAM の 30% = 15億円/年

SOM（Serviceable Obtainable Market）:
- 5年以内に実現可能な市場シェア
- 目標: 1% = 1.5億円/年
- これは年間 300社 × 50万円に相当

【2. 3C分析】

**Customer（顧客）**
- プライマリ: 10～100名の中堅企業 PM・リーダー
- セカンダリ: 営業管理者、制作・開発チームリーダー
- ニーズ:
  * Excel/メールでのタスク管理の非効率性を解決したい
  * チーム全体のタスク可視化
  * 期限管理の自動化

**Competitor（競合）**
- 直接競合: Asana, Trello, Notion, Monday.com
  * Asana: 高機能だが高価（1ユーザー1,350円/月）、複雑
  * Trello: シンプルだがチーム分析機能が弱い
  * Notion: 汎用で学習曲線が急
  * Monday.com: モダンだが日本語対応不十分
- 間接競合: Excel、Google Sheets、Slack
  * 既に企業内に存在、導入コスト 0
  * 機能性では劣るが、非常に高い代替品

**Company（自社）**
- TaskFlow の強み:
  * シンプルで直感的な UI（日本企業向けに最適化）
  * AI による優先度提案
  * Slack 統合による通知
  * 手頃な価格（500円/ユーザー/月 を想定）
- 弱み:
  * ブランド認知ゼロ
  * 初期市場構築に時間要
  * スタートアップが多数

【3. 収益モデル】

BtoB SaaS モデル:
- 価格: 500円～1,000円/ユーザー/月
- 最小契約単位: 5ユーザー = 2,500～5,000円/月
- サポート: メール/チャット（初年度は無料）
- アップセル: プレミアムプラン（API, SSO, 高度な分析）

LTV（Life Time Value）とCAC（Customer Acquisition Cost）:
- 平均契約期間: 2年（24ヶ月）
- 平均チャーン率: 5%/月（初期段階）
- LTV = 月額 3,000円 × 24ヶ月 = 72,000円
- CAC 目標: 18,000円（LTV の 25%）

【4. 3年P&L予測】

**Year 1:**
- スタート: 月額経常収益 100万円（初期顧客400社）
- 成長率: 月 10%（SaaS典型値）
- 年間経常収益: 1,800万円
- 開発費: 1,500万円（人件費）
- マーケティング: 500万円
- インフラ・その他: 300万円
- **EBITDA: -1,300万円（赤字）**

**Year 2:**
- 月額経常収益: 200万円（顧客 800社）
- 年間経常収益: 3,600万円
- 開発費: 2,000万円
- マーケティング: 1,000万円
- インフラ・その他: 500万円
- **EBITDA: -900万円（改善中）**

**Year 3:**
- 月額経常収益: 400万円（顧客 1,600社）
- 年間経常収益: 7,200万円
- 開発費: 2,500万円（組織拡大）
- マーケティング: 1,500万円
- インフラ・その他: 800万円
- **EBITDA: 400万円（黒字化）**

【5. リスク・機会】

**ダウンサイドリスク:**
1. 競合の価格低下
   - Asana が年間 100円/ユーザーに値下げ
   - 対策: AI機能で差別化継続

2. チャーン率が予想より高い（10%/月）
   - 影響: Year 2 で黒字化遅延
   - 対策: オンボーディング改善、成功事例構築

3. 規制強化（GDPRなど）
   - 対策: 事前にコンプライアンス実装

**アップサイド機会:**
1. 企業数 50社の大口契約獲得
   - 月額 150万円の追加収益
   - Year 1 の赤字を 20% 削減

2. API/統合パートナーによる間接販売
   - 既存 SaaS（HR、ERP）との統合

3. 海外展開（東南アジア）
   - Year 3 から本格化、新市場開拓

完成した分析を markdown で出力してください。
```

### トラブル2: STRIDE分析がわからない
**解決策**: STRIDE の各カテゴリの定義を確認してください:

| 脅威 | 説明 | 例 |
|------|------|-----|
| Spoofing | ユーザー認証の偽装 | パスワード盗聴、セッション乗っ取り |
| Tampering | データの改ざん | タスクデータ無断修正、DB直接操作 |
| Repudiation | 行動の否認 | 「操作していない」と主張 |
| Information Disclosure | 情報漏洩 | ユーザーデータの流出、盗聴 |
| Denial of Service | サービス停止 | DDoS、過負荷攻撃 |
| Elevation of Privilege | 権限昇格 | 一般ユーザーが管理者権限を取得 |

AIに「STRIDE の具体例も示してほしい」と追加要望してください。

### トラブル3: 市場規模の推定方法がわからない
**解決策**: 市場規模推定には2つのアプローチがあります:

**トップダウン法:**
```text
1. 国内企業数（統計）→ ターゲット企業数 → 導入率 → 平均購買額
2. 例: 380万社 × 3% × 50% × 50万円 = 285億円
```

**ボトムアップ法:**
```text
1. 既存顧客（実績） → リーチ可能な市場 → 成長率
2. 例: 100社 × 100 × 20% 成長 = 2,000社市場規模
```

わからなければ複数の前提条件を明示して、「前提を変えるとこうなる」という感度分析を示してください。
