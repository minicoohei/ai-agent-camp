# 応用演習レビュー

## 使い方
```
/exercise-review [演習番号] [出力フォルダ]
```

例:
```
/exercise-review 4-2 output/ex4-2
/exercise-review 7-3 ~/projects/gas-demo
```

## 処理内容

### 1. 成果物の分析
- 出力フォルダ内のファイルを確認
- コード品質の評価
- 構成の確認

### 2. 演習要件との照合
各Moduleの演習要件を確認し、達成度を評価:
- 必須要件の充足
- オプション要件の実装状況
- ベストプラクティスへの準拠

### 3. 改善点のフィードバック
- コード品質の改善提案
- 設計パターンの推奨
- セキュリティ・パフォーマンスの観点

### 4. 次のステップ提案
- 追加で学ぶべきトピック
- 関連する応用演習
- 実践プロジェクトへの展開

## 評価基準

### コード品質
| 項目 | 評価基準 |
|------|----------|
| 可読性 | 命名規則、コメント、構造化 |
| 保守性 | モジュール分割、依存関係 |
| テスト | カバレッジ、エッジケース |
| エラー処理 | 例外処理、ログ出力 |

### 機能充足
| レベル | 説明 |
|--------|------|
| A | 全要件充足 + 追加機能 |
| B | 全必須要件充足 |
| C | 主要要件充足 |
| D | 一部要件のみ |

## 出力形式

```markdown
## 演習 [番号] レビュー結果

### サマリー
- 総合評価: [A/B/C/D]
- 完了度: [XX%]
- 主な強み:
- 改善点:

### 詳細評価

#### 機能要件
| 要件 | 状態 | コメント |
|------|------|----------|
| 要件1 | OK/NG | ... |
| 要件2 | OK/NG | ... |

#### コード品質
- 可読性: [X/5]
- 保守性: [X/5]
- テスト: [X/5]
- エラー処理: [X/5]

### 改善提案
1. [優先度:高] ...
2. [優先度:中] ...
3. [優先度:低] ...

### 次のステップ
- 関連演習: start-X-X
- 参考資料: [URL]
```
