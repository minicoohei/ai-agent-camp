# meeting-notes-summarizer - 議事録自動生成スキル

## いつ使うか

以下のようなリクエストを受けたときにこのスキルを使用する:

- 会議のテキストやメモから議事録を作成してほしいとき
- アクション項目や決定事項を抽出してほしいとき
- 会議メモを構造化・整理してほしいとき
- ミーティングノートをフォーマットしてほしいとき

トリガーフレーズ例:
- 「議事録をまとめて」
- 「会議メモを整理して」
- 「アクション項目を抽出して」
- 「ミーティングノートをまとめて」
- 「この会議の要点を整理して」
- 「決定事項をリストアップして」

## ワークフロー

このスキルは以下の手順で処理を行う:

### Step 1: 入力テキストの受け取り
- ユーザーから会議テキスト、メモ、音声書き起こしなどを受け取る
- テキストの形式（箇条書き、自由記述、チャットログ等）を判定する

### Step 2: 参加者の抽出
- テキスト中から参加者名・発言者名を特定する
- 名前の表記ゆれ（フルネーム、ニックネーム、敬称あり/なし）を統一する
- 参加者が明示されていない場合は「参加者不明」と記載する

### Step 3: 議題の特定
- 会議の主要トピックを時系列で特定する
- 各トピックの議論内容を要約する
- トピック間の関連性を整理する

### Step 4: 決定事項の抽出
- 「決定」「合意」「承認」「決まった」などのキーワードから決定事項を抽出する
- 各決定事項の背景・理由を簡潔に付記する
- 決定事項がない場合は「決定事項なし」と明記する

### Step 5: アクション項目の抽出
- 「やる」「対応する」「確認する」「次回までに」などのキーワードからアクション項目を抽出する
- 各アクション項目に担当者・期限を紐づける
- 担当者が不明な場合は「要確認」と記載する
- 期限が不明な場合は「期限未定」と記載する

### Step 6: 出力フォーマットへの整形
- references/output-template.md のテンプレートに従って出力を整形する
- Markdown 形式で構造化された議事録を生成する
- 出力先は output/ ディレクトリに保存する

## 出力フォーマット

出力は references/output-template.md に定義されたテンプレートに従う。
主要セクション:
- 基本情報（日時、参加者、場所/方法）
- 議題一覧
- 決定事項
- アクション項目（担当者、タスク、期限のテーブル形式）
- 次回予定

## エッジケースの対処

### アクション項目がない場合
- 「アクション項目」セクションに「今回のアクション項目はありません」と記載する
- 決定事項のみの会議もあるため、エラーとしない

### 参加者が不明な場合
- 発言内容から推測できる場合は「（推定）」を付けて記載する
- 完全に不明な場合は「参加者: 不明（テキストに記載なし）」と記載する

### 多言語が混在する場合
- 入力テキストの主要言語に合わせて出力する
- 固有名詞や技術用語は原語のまま保持する
- 日本語と英語が混在する場合は日本語を優先する

### 入力テキストが短すぎる場合
- 最低限の情報（議題と決定事項）のみで議事録を作成する
- 不足している情報については「記載なし」と明記する

### チャットログ形式の場合
- タイムスタンプと発言者を解析する
- 雑談やノイズを除外し、議論の本質を抽出する
- スレッド形式の場合はスレッドごとにトピックを分類する

500行以内、5000語以内に収めてください。
```

**期待される結果**: SKILL.md にワークフロー手順、出力仕様、エッジケース対処が記述されます。

### トラブル1: SKILL.md がトリガーされない
**原因**: description にトリガーフレーズが不足している
**解決プロンプト**:
```
SKILL.md の YAML フロントマター内の description を確認してください。

以下のポイントをチェック：
1. description にトリガーフレーズが含まれているか
   例: 「議事録をまとめて」「会議メモを整理して」
2. name フィールドが正しいケバブケースになっているか
3. YAML の構文エラーがないか（インデント、クォート）

修正例:
description: 会議テキストやメモから構造化された議事録を自動生成するスキル。「議事録をまとめて」「会議メモを整理して」「アクション項目を抽出して」と言われたときに使用する。
```

### トラブル2: 出力フォーマットが不統一
**原因**: 出力テンプレートの参照が不足している
**解決プロンプト**:
```
SKILL.md の「出力フォーマット」セクションを確認してください。

以下をチェック：
1. references/output-template.md が存在するか
2. SKILL.md 内でテンプレートファイルへの参照パスが正しいか
3. テンプレートのプレースホルダーが統一されているか

テンプレートファイルの確認：
cat skills/meeting-notes-summarizer/references/output-template.md
```

### トラブル3: ディレクトリが認識されない
**原因**: skills/ 直下に正しく配置されていない
**解決プロンプト**:
```
ディレクトリの配置を確認してください。

正しい配置:
skills/meeting-notes-summarizer/SKILL.md

以下のコマンドで確認：
ls -la skills/meeting-notes-summarizer/

よくある間違い:
- .claude/skill/ （skills ではなく skill になっている）
- skills/meeting-notes-summarizer/ （正しいパス。ハイフン区切り）
- SKILL.md が別のディレクトリに配置されている
```

### トラブル4: description が長すぎてエラー
**原因**: description が冗長になりすぎている
**解決プロンプト**:
```
description を100語程度に凝縮してください。

ポイント:
1. スキルの機能を1文で説明する
2. トリガーフレーズは代表的なもの3〜4個に絞る
3. 詳細な説明は SKILL.md 本文に移動する

凝縮前（悪い例）:
description: このスキルは会議のテキストデータやメモ書き、音声の書き起こしテキストなどを入力として受け取り、参加者の特定、議題の整理、決定事項の抽出、アクション項目の洗い出しを行い、構造化されたMarkdown形式の議事録として出力する高度なテキスト処理スキルです。

凝縮後（良い例）:

## ➡️ 次のステップ

これでこのセクションは完了です。次のセクションを始めるか、新しいウィンドウを開いて、新しいセクションを開始してください。

AskUserQuestion（AskQuestion）で選べます。

**AskQuestionの設定例:**
```json
{
  "title": "次のステップを選択",
  "questions": [{
    "id": "next_step",
    "prompt": "次に進む操作を選んでください",
    "options": [
      {"id": "next_auto", "label": "次のセクションを開始（/next_lesson）"},
      {"id": "next_window", "label": "新しいウィンドウで開始（/start-7-3）"},
      {"id": "finish", "label": "ここで終了する"}
    ]
  }]
}
```

**選択後の案内（例）**:
- next_auto → /next_lesson
- next_window → 新しいウィンドウで /start-7-3
- finish → 終了
