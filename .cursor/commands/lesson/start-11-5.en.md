**Guidance after selection:**

Create `tools/build_site.py` (a simple static site generator):

```python
#!/usr/bin/env python3
"""Simple static site generator"""
import os
import json
from datetime import datetime

def build():
    os.makedirs("dist", exist_ok=True)
    
    # Generate index.html
    html = f"""<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>AI Agent Camp — Build Artifact</title>
  <style>
    body {{ font-family: sans-serif; max-width: 800px; margin: 2rem auto; padding: 0 1rem; }}
    .meta {{ color: #666; font-size: 0.9rem; }}
  </style>
</head>
<body>
  <h1>AI Agent Camp</h1>
  <p class="meta">Built at: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}</p>
  <p>This page was auto-generated by GitHub Actions.</p>
</body>
</html>"""
    
    with open("dist/index.html", "w") as f:
        f.write(html)
    
    # Generate build-info.json
    info = {
        "built_at": datetime.utcnow().isoformat(),
        "commit": os.environ.get("GITHUB_SHA", "local"),
        "ref": os.environ.get("GITHUB_REF", "local"),
    }
    with open("dist/build-info.json", "w") as f:
        json.dump(info, f, indent=2)
    
    print("Build complete: artifacts generated in the dist/ directory")

if __name__ == "__main__":
    build()
```

```bash
python tools/build_site.py && ls -la dist/
```

**Expected result:** `index.html` and `build-info.json` are generated in the `dist/` directory.

## 🚀 Step 2: Upload and Save Artifacts

```json
{
  "title": "🚀 Step 2: Artifact Management",
  "questions": [{
    "id": "step_action",
    "prompt": "Create a workflow that saves build artifacts as GitHub Actions artifacts.",
    "options": [
      {"id": "practice", "label": "Proceed"},
      {"id": "review", "label": "Review how artifacts work"},
      {"id": "skip", "label": "Skip"}
    ]
  }]
}
```

**Guidance after selection:**

Create `.github/workflows/build-and-deploy.yml`:

```yaml
name: Build and Deploy
on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Build site
        run: python tools/build_site.py

      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: site-build-${{ github.run_number }}
          path: dist/
          retention-days: 30

      - name: Build summary
        run: |
          echo "## Build Artifacts" >> $GITHUB_STEP_SUMMARY
          echo "| File | Size |" >> $GITHUB_STEP_SUMMARY
          echo "|---------|-------|" >> $GITHUB_STEP_SUMMARY
          for f in dist/*; do
            SIZE=$(wc -c < "$f" | tr -d ' ')
            echo "| $(basename $f) | ${SIZE} bytes |" >> $GITHUB_STEP_SUMMARY
          done
```

**Key points:**
- Use `actions/upload-artifact@v4` to save build artifacts
- Specify retention period with `retention-days` (default is 90 days)
- Display build info in the workflow summary using `$GITHUB_STEP_SUMMARY`

**Expected result:** After workflow execution, an artifact download link appears in the Summary on the Actions tab.

```json

  "title": "🚀 Step 3: GitHub Pages Deploy",
  "questions": [{
    "id": "step_action",
    "prompt": "Deploy build artifacts to GitHub Pages.",
    "options": [
      {"id": "practice", "label": "Proceed"},
      {"id": "review", "label": "Review how to configure GitHub Pages"},
      {"id": "skip", "label": "Skip"}
    ]
  }]
}
```

**Guidance after selection:**

Add a Pages deploy job to the workflow:

```yaml
  deploy-pages:
    needs: build
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Build site
        run: python tools/build_site.py

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: dist/

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

**Pre-configuration:**
1. Go to the repository's Settings → Pages
2. Source: Select "GitHub Actions"

**Expected result:** The site is published at `https://<owner>.github.io/<repo>/`.

```json
{
  "title": "🚀 Step 4: Vercel Deploy",
  "questions": [{
    "id": "step_action",
    "prompt": "Deploy from GitHub Actions using the Vercel CLI.",
    "options": [
      {"id": "practice", "label": "Proceed"},
      {"id": "review", "label": "Review how to configure Vercel"},
      {"id": "skip", "label": "Skip (use GitHub Pages only)"}
    ]
  }]
}
```

**Guidance after selection:**

Create `.github/workflows/vercel-deploy.yml`:

```yaml
name: Vercel Deploy
on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Build
        run: python tools/build_site.py

      - name: Install Vercel CLI
        run: npm install -g vercel

      - name: Deploy to Vercel
        env:
          VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
          VERCEL_ORG_ID: ${{ secrets.VERCEL_ORG_ID }}
          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
        run: |
          vercel deploy dist/ --prod --token=$VERCEL_TOKEN \
            --yes --cwd .
```

**Values to set in Secrets:**
- `VERCEL_TOKEN`: Generate in Vercel Dashboard → Settings → Tokens
- `VERCEL_ORG_ID`: Obtain from `.vercel/project.json` after running `vercel link`
- `VERCEL_PROJECT_ID`: Same as above

**Expected result:** Deployment to Vercel occurs on every push, and a preview URL is issued.

## 🚀 Step 5: Auto-Generate Release Notes

```json
{
  "title": "🚀 Step 5: Auto-Generate Release Notes",
  "questions": [{
    "id": "step_action",
    "prompt": "Automatically generate release notes triggered by a tag push.",
    "options": [
      {"id": "practice", "label": "Proceed"},
      {"id": "review", "label": "Review how gh release works"},
      {"id": "skip", "label": "Skip"}
    ]
  }]
}
```

**Guidance after selection:**

Create `.github/workflows/release.yml` (or extend an existing one):

```yaml
name: Release
on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Build
        run: python tools/build_site.py

      - name: Create release archive
        run: |
          cd dist && tar czf ../release-${{ github.ref_name }}.tar.gz .
          cd .. && zip -r release-${{ github.ref_name }}.zip dist/

      - name: Generate release notes
        run: |
          # Get commit log from the previous tag to the current tag
          PREV_TAG=$(git tag --sort=-creatordate | head -2 | tail -1)
          echo "## Changes" > release_notes.md
          echo "" >> release_notes.md
          git log ${PREV_TAG}..HEAD --pretty=format:"- %s (%h)" >> release_notes.md

      - name: Create GitHub Release
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          gh release create ${{ github.ref_name }} \
            --title "Release ${{ github.ref_name }}" \
            --notes-file release_notes.md \
            release-${{ github.ref_name }}.tar.gz \
            release-${{ github.ref_name }}.zip
```

**Test procedure:**
```bash
# Create and push a tag
git tag v1.0.0
git push origin v1.0.0

# Check the release
gh release list
```

**Expected result:** A tag push automatically creates a release with build artifacts attached.

## ⚠️ Common Issues and Solutions

```json
{
  "title": "⚠️ Troubleshooting",
  "questions": [{
    "id": "trouble",
    "prompt": "Are you experiencing any issues?",
    "options": [
      {"id": "trouble_1", "label": "GitHub Pages deployment failed"},
      {"id": "trouble_2", "label": "Vercel deploy error"},
      {"id": "trouble_3", "label": "Artifact cannot be downloaded"},
      {"id": "trouble_4", "label": "Release not created"}
    ]
  }]
}
```

### Issue 1: "GitHub Pages deployment failed"
**Cause**: Pages Source is not set to "GitHub Actions", or permissions are missing.
**Solution prompt:**
```text
Check that "GitHub Actions" is selected under Settings → Pages → Source in the repository. Verify that the workflow has pages: write and id-token: write permissions.
```

### Issue 2: "Vercel deploy error"
**Cause**: `VERCEL_TOKEN` is invalid, or the project is not linked.
**Solution prompt:**
```text
Run vercel link locally to link the project. Obtain ORG_ID and PROJECT_ID from .vercel/project.json and set them in Secrets.
```

### Issue 3: "Artifact cannot be downloaded"
**Cause**: The `retention-days` period has expired, or the path was specified incorrectly.
**Solution prompt:**
```text
Check the output of the upload-artifact step in the workflow logs. Verify that files exist in the directory specified by path.
```

### Issue 4: "Release not created"
**Cause**: The tag format does not match `v*`, or permissions: contents: write is missing.
**Solution prompt:**
```text
Verify that the git tag format starts with v, like v1.0.0. Try running the gh release create command locally to check the error message.
```
