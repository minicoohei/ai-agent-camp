# Slide Forge — 骨子からスライドを作る

骨子（アウトライン）やリサーチ結果をもとに、体裁の揃った自己完結HTMLスライド（16:9）を作成します。共通テンプレート（ヘッダー／フッター）を全枚に適用し、1枚＝1メッセージで構成します。出力は既定で自己完結HTML（外部CDN＝インターネット上の別サーバーから読み込むJS/CSSライブラリ・外部画像・外部フォントに依存しない）とし、ネット接続が無い環境でもファイルを開けば表示できる状態にします。

このスキルは特定プロジェクト専用ではなく汎用コマンドとして命名している。同名の `slide-forge` コマンドが環境に既に別定義で存在する場合は、導入時にその有無を確認し、無ければそのまま追加し、有る場合は本ファイルの内容を正として上書き・統合する。

## 機能

- 骨子ファイル（プロジェクトの慣例に従う。例: `outline/proposal.md`）やリサーチ結果（プロジェクトの慣例に従う。例: `research/<テーマ>/findings.md`）を入力に、外部依存の無い自己完結HTMLスライドを生成する
- 全ページ共通のヘッダー・フッター・配色・フォントを最初に固定し、体裁のブレを防ぐ
- 出典の無い数値・事実は使わない
- 画像はbase64データURIとしてHTMLに埋め込み、外部参照は作らない

## 使う／使わない判断

**使う**: リサーチ結果を提案デッキにしたい、骨子を投影用HTMLにしたい、既存メモの体裁を統一したい、多言語版スライドを量産したい、社内向けの軽量デッキが欲しい、写真・グラフ画像入りの提案デッキを作りたい、のいずれか。

**使わない（別の手段を検討）**:
- 緻密なアニメーション・画面切り替えが必要なPPTX（明示要求時のみ別途PPTX変換を検討）
- 1枚だけの単発図解・インフォグラフィック（→ `diagram-generator` スキルの方が適している）
- 既存のPowerPoint／Google Slidesテンプレートをそのまま直接編集したい場合
- 大量データを扱うインタラクティブなダッシュボードやフィルタ付きレポート（→ `interactive-dashboard-builder` スキルの方が適している）
- 出典のある事実・数値がまだ揃っていない段階（→ 環境に `ycp-research-factcheck` 等のファクトチェックスキルがあれば先にそれで済ませる。無ければ自前で出典を確認してから使う）
- 大量スライド（目安50枚超）や複数セクションに跨る長尺デッキ（→ 1ファイルが肥大化し保守困難になるため、章単位でファイルを分割するか枚数を絞ってから使う）

## 実行手順

1. **パラメータの抽出と保存先の確認**
   ユーザーの依頼から以下を抽出する。
   - 案件名・プロジェクト名（必須。ファイル名に使う）
   - 骨子ファイルの有無・パス（プロジェクトの慣例に従う。例: `outline/proposal.md`）
   - リサーチ結果・出典データの有無・パス（プロジェクトの慣例に従う。例: `research/<テーマ>/findings.md`）
   - 出力先（プロジェクトに慣例が無い場合はここでユーザーに確認する。無ければ既定は `output/slides/<プロジェクト名・テーマ名>.html`）

2. **骨子の確認**
   骨子ファイルがあれば内容を読み込む。無ければユーザーにヒアリングするか、環境に `ycp-proposal-outline` 等の骨子作成スキルがあればそれで章立て・キーメッセージを先に整理してから次に進む。数値・事実を使う場合は、出典付きのリサーチ結果があるか確認する（無ければ「出典が無い数字は使えない」旨を伝え、環境に `ycp-research-factcheck` 等のファクトチェックスキルがあれば案内する）。

3. **共通テンプレートの定義**
   1ファイル内のCSSで、以下を固定する。
   - サイズ: 16:9（1280×720）固定
   - 共通ヘッダー: 章ラベル＋タイトル
   - 共通フッター: プロジェクト名・ページ番号
   - 配色: 2色＋グレー階調まで。既定はネイビー（#1F3A5F）をメインカラー、オレンジ（#E8833A）をアクセントカラーとし、本文はグレー（#333333/#666666）。ブランドカラーが分かっている場合はそちらを優先する
   - フォント: システムフォントのみ（外部フォント読み込み禁止）。本文フォントサイズは18px以上を既定とする
   - 出典表記: 数値・事実を引用したスライドには、該当箇所の下に出典（媒体名・年月、または脚注番号）を8px前後の小さめの文字で明記する
   - 画像: 使う場合はbase64データURIとしてHTML内に埋め込む（外部ファイル参照・外部URLは禁止）。ファイルが極端に肥大化する場合は圧縮してから埋め込む

4. **1枚＝1メッセージでスライドを作成**
   - タイトル行はキーメッセージ（断定形の1行）にする。「〜について」のような説明的な見出しは使わない
     - 悪い例: 「市場動向について」
     - 良い例: 「国内市場は今後3年で1.5倍に拡大する」
   - ボディは箇条書き最大4個（1項目は日本語で全角40字以内が目安）、または図解1つまでにする
   - 図解が必要な枚は中央に図解エリアを確保する（プレースホルダでもよい。alt代替テキストを設定する）

5. **保存**
   プロジェクトの慣例（無ければ `output/slides/<プロジェクト名・テーマ名>.html`）に、外部CDN・外部画像・外部フォントに依存しない自己完結HTMLとして保存する。ブラウザで開けばそのまま投影できる状態にする。

6. **多言語版を作る場合**
   既定言語版を完成・レビューまで終えてから、同一テンプレートに翻訳文を流し込んで多言語版を生成する。ファイル名は言語ごとに `<同名>_<言語コード>.html`（例: `_ja.html` / `_en.html`）とする。文字量は言語によって増減するため、ボディの箇条書き文字数上限を言語ごとに再確認し、はみ出しがあれば文言を調整する（レイアウト自体は変更しない）。

7. **セルフレビュー**
   保存したHTMLファイルをダブルクリックして既定のブラウザで開き、実際に1枚ずつ表示を確認しながら、下記チェック項目に沿って確認する。問題があれば修正してから完了報告する。

## 使用例

```
/slide-forge outline/proposal.md をスライドにして
/slide-forge research/market-trends/findings.md を使って提案デッキを作って
/slide-forge 「AIエージェント導入提案」というテーマでスライド化して
```

## チェック項目（提出前）

- [ ] 1枚1メッセージになっているか（2つ以上の主張が混在していないか）
- [ ] タイトルだけを拾い読みして、全体のストーリーが通るか（確認方法: 全スライドのタイトル行だけを上から順に声に出して読み、話が急に飛んだり同じ話が繰り返されたりしていないか確認する）
- [ ] 全枚でヘッダー・フッター・余白・配色が統一されているか
- [ ] 出典のある数値・事実だけを使い、かつスライド上に出典表記（脚注またはフッター）があるか
- [ ] 自己完結HTMLになっているか（外部CDN・外部画像・外部フォントへの参照が残っていないか）
- [ ] 16:9（1280×720）で崩れずに表示されるか
- [ ] 本文フォントサイズが投影距離で読める大きさか（目安: 本文18px以上、箇条書き1項目は日本語で全角40字以内）
- [ ] 背景色と文字色のコントラストが十分か（薄いグレー文字を薄い背景に置いていないか）
- [ ] 色だけで意味を区別していないか（例: 赤=NG／緑=OKを色以外の記号・ラベルでも示しているか）
- [ ] 図解プレースホルダ・画像にalt代替テキストが設定されているか
- [ ] 保存先・ファイル名がプロジェクトの慣例（無ければ `output/slides/<名称>.html`）に沿っているか
- [ ] 誤字脱字、数字の桁・単位（円／ドル、％等）に誤りがないか
- [ ] 多言語版を作る場合、言語ごとに文字がはみ出したり、改行位置がおかしくなったり、フォントが崩れたりしていないか

## 注意事項
- 保存先は必ず `output/slides/` 配下に固定する。ファイル名は英数・ハイフン・アンダースコアのみに正規化し、`..`・先頭スラッシュ・制御文字を含む入力は拒否する（意図しない場所への書き込みを防ぐため）。

- PPTXでの出力はユーザーから明示的に要求された場合のみ検討する（既定はHTML）
- 骨子や出典データが無い状態でいきなりスライド化を始めない。先にステップ1〜2でインプットと保存先の慣例を揃える
- 1枚だけの単発図解や、緻密なアニメーションが必要なPPTXはこのコマンドのスコープ外
